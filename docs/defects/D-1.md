# D-1: `tally list` into a reader that stops early prints a stack trace

**Seen.** With 100,000 counters in `tally.json`, `tally list | head -1` printed the first line, then
wrote `node:events:497 throw er; // Unhandled 'error' event ... Error: write EPIPE` and a stack
trace on stderr, and exited 1. With a list small enough to fit the pipe's buffer (3,000 counters,
about 30 KB) nothing went wrong, so only a long list shows it.

**What is required.** TECH-SPEC section 10 (the user, Q20, D5): an unexpected internal error is
one `tally: …` line on stderr, never a stack trace. No PRD criterion said what `list` does when
its reader goes away; this defect adds one, REQ-02 acc. 11.

**Row.** T-REQ-02-P8 (`eval/tests/req-02-list-pipe.test.mjs`), new.

**Severity.** Wrong refusal: a stack trace where the blueprint forbids one, and a failure exit
where the person got exactly the lines they asked for.

**Found.** 2026-10-27, by the acceptance review of main `77bf564` (a session that built none of
tally), in its black-box pass; reproduced by the orchestrator the same evening.

**Decision.** 2026-10-27, the founder: fix now. Behaviour, in the founder's choice: "Silent,
exit 0": when the reader stops early, tally prints nothing on stderr and exits 0. Fixed by story 3.
