# list into a reader that stops early

Story 3 of tally, the fix for defect D-1 (`docs/defects/D-1.md`). It starts from stories 1 and 2
merged: all four commands work and all 76 earlier rows pass.

## What to build

- **REQ-02 acc. 11**: when the reader of `tally list`'s output stops reading before the end, as
  `tally list | head -1` does on a long list, tally prints nothing on stderr, exits 0, and
  `tally.json` is unchanged.

Today, with a long list, the write to stdout fails with `EPIPE` and the error escapes as a Node
stack trace, exit 1. Depending on the platform the error arrives either from the
`process.stdout.write` call inside `main` (caught, then printed as `tally: unexpected error: …`) or
afterwards, as an `error` event on `process.stdout` that nothing handles. Both must end silently
with exit 0. Any other error writing stdout keeps the rule of TECH-SPEC section 10 (D5): one
`tally: …` line on stderr, exit 1, no stack trace.

The change belongs in `app/bin/tally.js` only, where every failure is already mapped to a message
and an exit status (TECH-SPEC sections 2 and 13). No command module, `store.js` or `usage.js`
changes.
